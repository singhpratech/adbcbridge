Caveats for this run: Oracle and Db2 were measured while a CockroachDB container on the same host
was stuck in schema-change GC at ~5 cores (pyodbc is equally slow on them here, so it is the host, not
the bridge); a quiet-host run of the same shape gave 266k / 293k rows/s ingest and 1.9M / 5.7M rows/s
fetch (see `bench/BENCHMARKS.md`). pyodbc cells are pyodbc as it actually works against each driver:
`fast_executemany` segfaults on sqliteodbc and the Db2 clidriver and trips MonetDB's driver, and
MonetDB's `SQLEndTran` is a no-op under pyodbc, so those fall back to plain `executemany` and then
to autocommit per row (the harness retries in that order and verifies the row count). pyodbc cannot
connect through OdbcFb (Firebird). ClickHouse is run at 300 rows because clickhouse-odbc issues one
HTTP request per row.
