Now in the Apache Arrow ADBC documentation 🚀

Every ODBC driver, an Arrow driver.

adbcBridge is one plain-C shared library that turns whatever ODBC driver is on your machine into an ADBC driver — columnar Arrow batches out, bulk ingest in, from Python, Rust, Go, Java, C# and R. No per-database driver to write, no rows to convert by hand.

Rows on the near bank, columns on the far one. Nothing is lost on the way across.

What it is

The long tail of databases has an ODBC driver. Now it has an Arrow one.

Native ADBC drivers exist for a handful of databases. The other few hundred — Db2, Oracle, Informix, Vertica, Firebird, Access, every warehouse behind a PostgreSQL or MySQL wire — ship an ODBC driver and nothing else. adbcBridge sits between the ADBC driver manager and that ODBC driver, and does the columnar work once, in C, for all of them.

Where a native ADBC driver is installed (PostgreSQL, SQLite, DuckDB), the same install hands the connection to it, so you get native speed without changing a line.

The numbers

Three figures, each with its conditions attached.

Measured on four ordinary machines, never idle: a Linux laptop (Linux Mint 22.3, Core i9-13900HK, 14 cores, 31 GiB, unixODBC 2.3.12; the 53-database fleet on the same box — Docker containers and local files, Db2 for i alone on a public host —, ~23 GiB of other work resident), an Apple M4 Max (16 cores, 64 GB, load 2.4–10.5 during runs, some servers under amd64 emulation) and two Windows 11 laptops — the full 46-entry re-measure on a Core i9-13900HK (14 cores, 32 GB, Docker Desktop on WSL2, up to eight benchmark runs and ~30 idle containers at once), after the first campaign on a Core i7-8550U (4 cores, 7.7 GB, 26% run-to-run variance); both Windows builds without prefetch or fan-out. Cross-machine numbers are not comparable; each benchmark file opens with its host state.

How it works

Block cursors in, Arrow buffers out, and a few things only this driver does.

Reads

Columns are bound once with SQLBindCol into rowsets of up to 8 MiB and copied into Arrow buffers column-at-a-time; UTF-16 becomes UTF-8, decimals become decimal128, longs are chunked through SQLGetData. A column a driver describes as "unbounded" is bound at 2 KiB and re-read only when a value overflows, so one wide column no longer collapses the whole read to a row at a time.

Partitioned reads

AdbcStatementExecutePartitions splits one query into K slices — by ctid on a PostgreSQL heap, by key range on a leading primary-key column anywhere else, by yb_hash_code() on YugabyteDB — and reads them on K connections. The key column's NOT NULL comes from the catalog, never from "it is a primary key", so no row can fall between slices.

Writes

Bulk ingest binds parameter arrays where the driver honours them, and otherwise batches the stream into multi-row INSERT … VALUES, Oracle's INSERT ALL, or Firebird's UNION ALL SELECT — each form probed once per connection, and only after the plain form is refused. On PostgreSQL it sends INSERT … SELECT FROM unnest(arrays), 10,000 rows a statement, across up to 64 connections.

Delegation

adbc.odbc.delegate=auto looks for a native ADBC driver for the database behind the connection string and hands the whole driver over when one is found. The connection you configured is the connection you get; nothing is re-parsed.

Get it

Download the release, or build from source.

v0.1.0 carries the driver library for Linux x86_64 and aarch64, macOS arm64 and Windows x64, a Python wheel for each, the source distribution, the Rust crate, the NuGet package and the Maven jar with its sources and javadoc jars — fourteen files, every one built and tested by the release workflow from the tagged commit, with a SHA256SUMS to check them against. Releases after v0.1.0 add a GPG signature of that file, a build-provenance attestation per asset (gh attestation verify) and an SPDX SBOM; the security policy, the support window and the private reporting channel are in Security and verification.

Linux verified

sudo apt install unixodbc-dev cmake
git clone https://github.com/singhpratech/adbcbridge
cd adbcbridge
./install.sh          # into ~/.local, no root
pip install adbc-driver-manager pyarrow

The reference host: Linux Mint 22.3 (Ubuntu 24.04 base), unixODBC 2.3.12, the 53-database matrix on the same machine (Docker containers and local files; Db2 for i alone on a public IBM i host over TLS). install.sh builds the library into ~/.local and writes the driver manifest the ADBC driver manager already searches, so driver="odbc" resolves with nothing else set. Step by step: docs/getting-started/install-linux.md.

macOS verified

brew install unixodbc cmake sqliteodbc
cmake -S . -B build \
  -DCMAKE_PREFIX_PATH="$(brew --prefix unixodbc)"
cmake --build build

Apple M4 Max, macOS 26.5, arm64: 45 of 53 databases pass the compat workload, Oracle, Db2 and Informix on the vendors' arm64 drivers among them; vendor drivers that ship only iODBC-width builds run through a bridge built against iODBC. SQLite reads 2.3 M rows/s, DuckDB 4.2 M. The eight entries without a macOS driver or a runnable server are recorded with the reason. Details: bench/BENCHMARKS-macos.md, docs/getting-started/install-macos.md.

Windows verified

cmake -S . -B build
cmake --build build --config Release
# -> build\Release\libadbc_driver_odbc.dll

Windows 11 x64, MSVC 2022, the OS's own driver manager: 48 of 53 databases pass the complete workload under Docker Desktop on WSL2; the five remaining cells are recorded one by one: three driver-side failures, two databases whose vendor ships no Windows driver. CI builds and tests 64- and 32-bit Windows on every push to main and every pull request. Five Windows-only driver quirks are handled in the bridge — Firebird's driver name, Informix parameters, Arrow Flight SQL's text path (read as binary, 1.8× faster), Apache Ignite's narrow UTF-8 route and OpenLink Virtuoso's 4-byte indicator stride. The prefetch pipeline and parallel ingest are compiled out on Windows until a Win32 thread shim lands (on the roadmap). Details: bench/BENCHMARKS-windows.md, docs/getting-started/install-windows.md.

Giving back

What the sweep found in other projects, reported with a reproduction.

Driving 53 databases through one driver on three operating systems turns up defects that belong upstream. Each goes back to its project with a reproduction that needs nothing from this one.

unixODBCfiled

The driver manager overwrites its own stack and heap, and the process aborts, on the first SQL error from a driver whose SQLWCHAR is 4 bytes. Found on macOS with two vendor drivers; reproduced on Linux with a 40-line fake driver; affects 2.3.12 and 2.3.14.

lurcher/unixODBC#239
OpenLink Virtuosofiled

The macOS driver is built to iODBC's 4-byte SQLWCHAR and nothing says so — through unixODBC every application dies on its first SQL error. On Linux the ANSI driver treats SQL_C_WCHAR as wchar_t on both sides, stores and reads SQL_C_SBIGINT as 0, steps date parameter arrays by ColumnSize, and aborts on any Charset= but the literal UTF-8 — four programs.

openlink/virtuoso-opensource#1469 · #1470 · #1471 · #1472 · #1473
Arrow Flight SQL ODBCfiled

The Apple Silicon build has the same undocumented width, a logger that breaks SQLAllocHandle when enabled, and docs that contradict each other on Apple Silicon support.

dremio/warpdrive#16
Firebird ODBCfiled

Column-wise parameter arrays step fixed-length C types at the BufferLength stride, so every row receives row 1's values; a SQL_BIGINT parameter once bound as SQL_C_DEFAULT keeps writing NULL; SQLPrepare discards the rows-fetched pointer set before it. Three plain-ODBC programs, reproduced on 3.0.1 and 3.5.0-rc1.

firebird-odbc-driver#299 · #300 · #301
taos-odbc (TDengine)filed

Timestamp columns cannot be bound (SQLGetData converts them, SQLBindCol does not), timestamp parameters and most BOOL parameter types are refused, and a DECIMAL column fails the whole SELECT — each with the driver's own diagnostic and a program.

taosdata/taos-connector-odbc#63
Apache Dorisfiled

Server-side prepare refuses a string parameter sent with MySQL type BLOB — what MySQL Connector/ODBC sends for every SQL_C_WCHAR parameter — so Unicode ODBC clients cannot insert through prepared statements: a NullPointerException on 2.1.0, a clean refusal on 4.1.3.

apache/doris#67301
clickhouse-odbcfiled

A bound SQL_NULL_DATA is ignored whenever a value buffer is attached, and parameter arrays stop after set 1 — the driver's one-set-per-SQLMoreResults protocol answers SQL_NO_DATA on the first call. Two programs; the affected-row count thread from 2021 re-measured on 1.5.5.

ClickHouse/clickhouse-odbc#582 · #335
psqlodbcfiled

An out-of-range int8 is narrowed to SQL_C_SLONG silently — 9223372036854775807 reads as −1 under SQL_SUCCESS; and with Protocol=7.4-0 a statement freed inside a transaction still sends SAVEPOINT;DEALLOCATE;RELEASE, whose failure on a server without savepoints is swallowed while COMMIT reports success. Wire captures included.

postgresql-interfaces/psqlodbc#207 · #208
QuestDBfiled

A BINARY column in a simple-query result is sent with format code 1 where PostgreSQL always sends text, so libpq and psqlodbc both cut the value at its first 0x00; and DEALLOCATE ALL throws a NullPointerException even on a fresh connection.

questdb/questdb#7566 · #7567
CrateDBfiled

A multi-statement simple query returns every CommandComplete tagged with the whole string's leading text — BEGIN;INSERT 0, BEGIN;INSERT 1 — so tag-parsing clients get no row count inside a transaction. Side by side with PostgreSQL at the wire level.

crate/crate#20085
OpenSearch SQL ODBCfiled

Any character value converted to SQL_C_TYPE_TIMESTAMP comes back as today's date under SQL_SUCCESS; and SQLErrorW never clears the connection error, so unixODBC loops forever on any failed connect. Both traced to the source line.

opensearch-project/sql-odbc#101 · #102
Apache Ignite ODBCfiled

Column-wise parameter arrays test row 0's NULL indicator for every row: a NULL below it stores an empty string, or segfaults the client on a binary column when WriteInt8Array is handed −1 as a length. The offending lines in parameter.cpp, with a fix.

apache/ignite#13537
MySQL Connector/ODBCfiled

SQLDescribeCol describes a DATETIME(6) as 19 characters with 0 digits while returning 26; and a MySQL-wire server reporting a zero charset width makes SHOW VARIABLES kill the client with SIGFPE in get_column_size().

mysql/mysql-connector-odbc#20 · #21
Materializefiled

DEALLOCATE "Name" keeps the quotes in its lookup, so a statement prepared at the protocol level with a mixed-case name — psqlodbc's _PLAN0x… — can never be released, and inside a transaction the failure aborts it. The server half of the psqlodbc row-loss pair; filed with a psycopg side-by-side against PostgreSQL 16, which releases it.

MaterializeInc/materialize#38605
SingleStore Connector/ODBCfiled

SQLGetTypeInfo fails with 42S22 Unknown column 'json' whenever sql_mode contains ANSI_QUOTES: the type-info result set is built from a SQL template with double-quoted string literals, which that mode turns into identifiers. And SQLColumns with a NULL catalog name segfaults the client on a connection opened without Database= — strdup(NULL) on the client library's empty current-database field. Both reproduced through pyodbc alone, with the source lines named.

memsql/singlestore-odbc-connector#45 · #46

Twenty-seven reports across fifteen projects so far; forty more findings — connector versions, driver bindings, server behaviours, container images, and one (MatrixOne's BIT arrays) fixed on their main before it could be filed — are documented with their first error and conditions in docs/UPSTREAM.md.

Five packages, one library inside each.

Each package finds the library the same way — an explicit override (ADBC_ODBC_DRIVER everywhere, ADBCBRIDGE_LIBRARY too in Rust, C#, Java and Go), the copy shipped inside the package, the ADBC driver manifest, the usual install directories — and Rust, C#, Java and Go list every place they looked in the error. All five are built and tested in the repository and attached to every release — v0.1.0 is the first — and published on PyPI, crates.io, NuGet, Maven Central and as a Go module.

Stated rather than hidden. Three of those drivers were built from source for Linux here (Ignite, OpenSearch, TDengine); Ignite and OpenSearch publish no Linux build at all. Oracle's driver segfaults if a rowset is resized on an open LOB cursor, so the reader never does.
